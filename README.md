# SORT / LAB

Python 정렬 코드를 입력하고 배열의 변화와 비교 연산을 애니메이션으로 살펴보는 정적 웹 서비스입니다.

**접속:** https://dm.kookmin.ac.kr/sorting/

https://kmudmlab.github.io/sorting/ 주소로 접속해도 같은 사이트로 이동합니다.

## 사용 방법

1. 버블·선택·삽입·퀵·병합 정렬 예제를 선택하거나 `sort(arr)` 함수를 작성합니다.
2. 숫자 배열을 입력하고 **실행 & 재생**을 누릅니다.
3. 이전·다음 단계, 슬라이더, **다음 비교** 버튼으로 실행 과정을 살펴봅니다.

비교 단계에서는 왼쪽 피연산자 A와 오른쪽 피연산자 B, 실제 값과 비교 결과를 표시합니다. 배열 원소를 비교하면 해당 위치를 강조하고, 별도 변수나 보조 배열과의 비교도 구분합니다.

## 실행 및 배포

- `index.html` 하나에 화면, 실행기, 예제 코드가 들어 있습니다. 브라우저에서 파일을 직접 열어도 실행할 수 있습니다.
- Python 실행기는 Pyodide 0.27.7을 사용합니다. 최초 실행 시 CDN에서 불러오므로 인터넷 연결이 필요합니다.
- 사용자 코드는 브라우저의 Web Worker 안에서 실행됩니다.
- 입력은 −9999부터 9999 사이 숫자를 최대 60개 지원합니다. 기록은 최대 12,000단계이며 실행 제한 시간이 있습니다.
- GitHub Pages는 `main` 브랜치의 루트(`/`)에서 배포합니다. `index.html`을 수정해 올리면 사이트에 반영됩니다.

`sorted()`와 `list.sort()` 내부의 개별 연산은 시각화하지 않습니다.

## 구현 과제

**과제 주소:** https://dm.kookmin.ac.kr/sorting/assignments.html

- 퀵 정렬의 `partition(arr, l, r)`: 마지막 원소를 피벗으로 분할, O(n) 목표.
- 병합 정렬의 `merge(arr, l, m, r)`: 정렬된 두 구간 병합, O(n) 목표.
- 힙 정렬의 `siftdown(arr, root, size)`: 최대 힙 복구, O(log n) 목표.

학생은 함수 본문만 편집합니다. 함수 이름·인수·전체 정렬 코드는 고정되어 있습니다.
즉시 채점하며 횟수 제한 없이 수정하고 재도전할 수 있습니다.
현재 dmlab 과제 서비스는 과제 목록과 개별 구현·채점·제출 화면으로 구성되며, 정렬 시각화는 포함하지 않습니다.

### 채점

함수 단독 정확성 40점, 고정 코드와 전체 정렬 정확성 40점,
입력 크기별 정확성 및 연산 수 기준 20점입니다.
연산 수는 n = 64, 128, 256, 512, 1024에서 여러 입력을 검사합니다.
partition/merge는 `100n + 160`, siftdown은 `120 ceil(log2(n+1)) + 120`을 사용합니다.
기본 문장·식 평가·반복·대입·접근을 세며 슬라이스·복사·배열 연산·min/max도 원소 수만큼 셉니다.
이는 유한한 입력에서 연산 예산을 충족하는지 검사하는 것이며 점근적 복잡도의 증명은 아닙니다.

제한된 Python AST 실행기를 사용합니다. 내장 정렬, import, 별도 함수 정의 등은 허용하지 않습니다.
지원 문법과 연산 예산은 과제 화면에 공개되어 있습니다.

### 학교 계정 로그인과 제출

현재 과제 서비스: https://dmlab.kookmin.ac.kr:8766/assignments.html

학교 Google 계정(@kookmin.ac.kr)으로 로그인하고 학번을 입력합니다. 학번 자체는 학교 명부와 자동 대조하지 않습니다.
연습 채점은 브라우저에서 진행하고, 각 과제의 최종 제출은 dmlab 서버가 다시 채점하여 SQLite에 저장합니다.
로그인한 학생은 본인의 제출 이력·최신 점수·최고 점수·제출 코드를 확인할 수 있으며 재제출도 가능합니다.
각 과제는 독립된 100점 만점입니다. 과제 목록에서 제출 여부를 확인하며 교수자는 과제를 선택해 전체 제출 현황을 확인합니다. 기존 SQLite 일괄 제출 기록은 원본을 유지하고 과제별 점수로 연결합니다.

기존 Google Form 기록은 보존되며 `assignments-legacy.html`에서 접수 번호로 조회할 수 있습니다.
이전 화면의 새 제출은 종료했습니다. 새 기록은 로그인 계정에 귀속되므로 이전 자가 입력 학번과 자동으로 합치지 않습니다.

### 개발

`assignment_engine.py`가 고정 정렬 코드와 브라우저 채점기를 정의합니다.
`assignments.template.html`은 이전 과제 UI입니다. `submission-api.json`의 portalUrl이 있으면 새 로그인 사이트 안내와 이전 조회 전용 페이지를 빌드합니다.
`submission-form.json`은 이전 폼 직접 제출 방식의 미사용 설정입니다.

```sh
python3 -m unittest test_assignments -v
python3 build_assignments.py
python3 -m http.server 8765 --bind 127.0.0.1
```

현재 빌드된 `assignments.html`은 dmlab 과제 목록으로 연결하는 안내 페이지입니다.
이전 코드·접수 조회용 `assignments-legacy.html`과 정렬 시각화 `index.html`은 기존 공개 주소에 보존합니다.
최종 제출은 학교 계정으로 dmlab 과제 서비스에서 진행하세요.

현재 로그인·SQLite 서버는 dmlab의 비공개 작업 폴더에서 운영합니다. 공개 저장소에는 서버 비밀키나 제출 DB를 넣지 않습니다.
공개 운영 안내는 `server/README.md`에 있습니다.
